## Test environment notes
Traps found while automating checks; they waste time if forgotten.

- **whisper.cpp builds unoptimized unless told** (spec 19): the `cmake` crate replaces CMake's release flags with its own, without `-O2`, so 5 s of speech took 72 s. `.cargo/config.toml` sets `CMAKE_C_FLAGS_RELEASE`. `CFLAGS=-O2` doesn't help: the crate strips optimization flags from it. And `whisper-rs-sys`'s build script doesn't watch these variables, so after changing them run `cargo clean -p whisper-rs-sys`.
- **The laptop's build tools for voice input** live outside the repo: CMake from the Visual Studio Build Tools and libclang from PyPI (`D:	ools\libclang`), named in `%USERPROFILE%\.cargo\config.toml`. Its WSL has no sudo, so CMake (Kitware's tarball) and ALSA's headers (`apt-get download libasound2-dev`, unpacked) are in `~/tools`, set up by `~/.cursora-env`, which `scripts/wsl-test.sh` sources. On Linux, `WHISPER_DONT_GENERATE_BINDINGS=1` is needed without libclang: bindgen panics instead of falling back.
- **Tesseract in the laptop's WSL** is unpacked from Ubuntu's packages (`tesseract-ocr`, `libtesseract5`, `liblept5`, `libarchive13t64`, the `eng` and `osd` data) into `~/tools/tesseract`, with a wrapper in `~/tools/bin` that sets `LD_LIBRARY_PATH` and `TESSDATA_PREFIX`; `~/.cursora-env` puts it on the PATH. Without it, the OCR test skips itself on Linux.
- **A long test recording hears the room.** A minute of "silence" for the 60-second check transcribed a video playing nearby. Keep test recordings short, and play the question through the speakers with Windows' text-to-speech.

- **WSL has its own Wayland display (WSLg).** GTK picks it over the test X server, so Linux Cursora windows appear on the Windows desktop. Tests set `unset WAYLAND_DISPLAY; export GDK_BACKEND=x11`. (Early in the spec 03 X11 run, a Linux bubble may have flashed on the Windows screen because of this.)
- **GTK creates a hidden window's X window only when it is first shown**, so the bubble can't be found before the first hotkey. GTK's helper window is also named "cursora", and `xdotool search --name` ignores case: search `--onlyvisible`.
- **`xwininfo` and `xprop` wait for a mouse click when given no window id**, which hangs a script.
- **`xdotool getwindowgeometry` reports positions relative to the window manager's frame**; `xwininfo` gives absolute ones.
- **`pkill -f "<pattern>"` inside `bash -c "...<pattern>..."` kills its own shell.**
- **Windows PowerShell 5.1 reads a script without a byte order mark as ANSI**: keep test scripts ASCII, and write Unicode as `\uXXXX`.
- **Windows PowerShell 5.1 drops a bare `--` before a native command's arguments**: `npm run tauri build -- --debug --no-bundle` reached npm as `--debug`, and Tauri made a release build with installers. Run it from Git Bash, or as `npx tauri build --debug --no-bundle`.
- **PowerShell variable names ignore case**: `$out` overwrites `$Out`, `$c` overwrites `$C`.
- **Test scripts must never type into the user's apps.** In one run, keystrokes meant for Cursora's Settings went to the user's Chrome window (a GitHub Copilot chat) when another window came to the front. The scripts now refuse to type, press Enter or Tab, or click unless the window in front belongs to Cursora or the test.
- **Windows reconnects Wi-Fi on its own** after `netsh wlan disconnect`; an offline test must keep disconnecting while it runs.
- **Edge's PDF viewer ignores Ctrl+A**; select by dragging.
- **The Desktop's icons aren't visible to UI Automation** from the test shell; select an icon by typing its name.
- **UI checks on Windows can't run while the screen is locked**: the foreground window is the lock screen, and the guard stops the script. Check for `LockApp` or `LogonUI` first: a locked screen can show either one.
- **WSL's PATH includes the Windows folders** (`/mnt/c/...`), which have spaces and are slow to look in. `env $VARS` splits such a PATH apart, so tests pass a short Linux-only PATH. And Cursora's `wl-paste` lookup on Wayland takes about 100 ms in WSL, against nothing on a real Linux.
- **Editing a bash script while it runs breaks it**: bash reads the file as it goes, so an edit shifts what it reads next ("syntax error near unexpected token"). Patch a copy, or wait until the run ends.
- **`atspi.py text` prints only the first match**; `all` prints every match.
- **Clicking the bubble's input at a fixed offset breaks when a spec adds a row**: spec 07's "What will be sent" row moved the input down, so the spec 04 script's click (+105 px) opened that row instead and the question was lost. Click near the bubble's bottom, where the input always is.
- **The Windows screen-grab test fails while the screen is locked** ("Windows didn't let Cursora copy the screen"): the lock screen is a secure desktop that BitBlt can't read. Run the Rust tests unlocked.
- **On Wayland there is no hotkey**, so a test can't close the bubble with Ctrl+G. A second `--ask` closes it, as the user's bound shortcut does; Esc never closes the bubble (BUB-2.3). So a test that asks again must close the bubble first, or its `--ask` only closes it.
- **WSL's tray host is stalonetray**: with no AppIndicator watcher, libayatana-appindicator falls back to an XEmbed icon, which stalonetray shows; a left click opens the menu, and AT-SPI sees the items (the popup has no title, so search the whole app).
- **A screen grab closes an open GTK menu** (ImageMagick's `import` breaks the menu's pointer grab): take screenshots after the clicks.
- **A PowerShell function named `Measure` never runs**: the `measure` alias (Measure-Object) wins over it, and its output disappears without an error. Name test helpers something else.
- **The Windows test window is always on top**, so it can cover the window under test and catch its clicks (the guard allows clicks on it): hide it first.
- **Newer WebView2 returns a Promise from `scrollIntoView`**: a React effect written as `() => el.scrollIntoView()` hands it back as the cleanup, and React crashes on the next run. Effects get a block body.
- **A render error leaves the page blank, and there is no console in the tests.** A temporary error boundary that prints the error on the page lets UI Automation read it.
- **Under WSL, Cursora's "Open folder" opens File Explorer on the Windows desktop**: the `open` crate detects WSL and hands the folder to `powershell.exe` before trying `xdg-open` or `gio`. A test that clicks it must look for Explorer windows (`Shell.Application`) and close them after. (WSL also has no `xdg-open`, and `gio` there has no default app for folders.)
- **Claude's memory is the repo's `memory/` folder** (a junction made by `scripts/link-memory.ps1`), so checking out a branch without a memory change hides that change from Claude until the branch is merged.
- **A second, test copy of Cursora next to the installed one needs its own identifier and product name**: `npx tauri build --debug --no-bundle --config '{"identifier":"com.cursora.dev","productName":"Cursora Dev"}'`, with its own `%APPDATA%\com.cursora.dev\settings.json` (setup done, Start with system off, hotkeys that don't clash). With the same identifier its commands only reach the installed copy; with the same product name, its "Start with system: off" deletes the installed copy's "Cursora" Run entry.
- **A test window hosted by `powershell.exe` gets no Replace or Insert**: PowerShell is on the "Ctrl+C may stop a process" list (WRT-3.1). Compile the window to its own exe (`Add-Type -OutputAssembly x.exe -OutputType WindowsApplication`).
- **Keys sent with `keybd_event` or `SendInput` need real scan codes for the page**: the bubble's Alt+1 to Alt+6 (QAC-1.2) read `KeyboardEvent.code`, which WebView2 takes from the scan code. With scan code 0 it is empty and nothing happens, though a real keyboard works. Send Alt as `0x12, 0x38` and 1 as `0x31, 0x02`.
- **The Windows folder picker ("Select Folder") exposes no UI Automation patterns** to a test script: its Folder box and buttons show up as plain panes. It's a top-level window of Cursora's process, not a child of Settings. Drive it with Win32 messages: `WM_SETTEXT` to dialog item 1152, then `BM_CLICK` to item 1. Also, Windows PowerShell 5.1 reads a `.ps1` without a BOM as ANSI, so a name with "…" never matches; save scripts with a BOM, or write `[char]0x2026`.
- **Another program can hold the clipboard open for minutes** (seen 2026-10-26 on the laptop: `Get-Clipboard` failed for over 30 s, `GetOpenClipboardWindow` returned no window, and quitting Cursora's test copy didn't free it). The write-back and quick-action tests compare the clipboard before and after, so they stop. Check a model without the clipboard instead: Settings → Models → Test connection, or a request to the engine's local port.
- **Tauri's mock app doesn't start on Windows**: with the `tauri` feature `test`, the lib test program exits with `STATUS_ENTRYPOINT_NOT_FOUND` (0xc0000139) before any test runs. The app's manifest isn't in test programs, which likely matters. Spec 11 tests the updater's signature check without it.
- **The WSL engine lives in `~/cursora/src-tauri/llama/`**, copied from `~/llama-b11570` (fetched and SHA-256 checked by the test script). Syncing the repo from D: must not overwrite it with the Windows engine.
- **The stronger PC's WSL had no X11 test tools** (the earlier X11 runs were on the laptop's WSL). Installed system-wide with `wsl -d Ubuntu-24.04 -u root` on 2026-10-26, `--no-install-recommends`: openbox, xdotool, stalonetray, imagemagick, xclip, mousepad, xterm, python3-pyatspi, gir1.2-atspi-2.0 and fonts-noto-core (the Indian scripts and Urdu). `apt remove` takes them out.
- **Calling `wsl` from Git Bash or PowerShell mangles a quoted script** (`$var`, `;`): write the step to a file and run `wsl -d Ubuntu-24.04 -u cursora -- bash /mnt/c/.../step.sh`. From Git Bash, also set `MSYS_NO_PATHCONV=1`, or it rewrites `/mnt/c/...` into a Windows path.
- **An open drop-down list in Settings holds the keyboard on X11**: while it's open, Ctrl+G doesn't reach Cursora and typing goes to another window. Close it (Escape) before pressing the hotkey.
- **`CURSORA_ECHO` answers instead of the chosen model in debug builds**, while the bubble's switcher still shows the default model. Start without it to try a real model.
- **`openbox --replace` focuses the window under the mouse as it starts**, which can make a failing focus check pass by accident (it did once in the X11 check of WRT-1.1). Restart the window manager before a check, not during it.
- **Background processes started in one `wsl` call die with it** unless started with `setsid` (an `xclip` holding the clipboard did); the X11 session itself ran as one long background `wsl` call.
